## Executive Summary

This report documents the Phase 02 work for Team TerraModel. During Weeks 4 through 6 we built a reproducible data pipeline, ran baseline models on three detection agents, and integrated an orchestrator that tags every finding with a MITRE ATT&CK for ICS technique ID.

Every number in this report comes from code in this repository. One command (`make all`) reproduces the dataset, baselines, and metrics.

## 1. Project Context

Automated warehouses run on operational technology. Traditional IT security tools do not watch robots, PLCs, and industrial sensors closely. When an attacker gets in, damage shows up as a stopped line, a damaged robot, or a safety incident. Our three-agent plus orchestrator design detects these threats and speaks the industry's own vocabulary through ATT&CK for ICS tagging.

Field data from 2025 supports the problem framing: manufacturing ransomware rose 56% year over year to 1,466 incidents (Industrial Cyber, 2026), OT sites with physical impact rose 146% year over year in Q3 2025 (DeNexus, 2025), and 46% of CISA ICS advisories target critical manufacturing systems (Security Boulevard, 2025).

## 2. Week 4: Data Acquisition and Collection

### 2.1 Data Sources

| Source | What It Provides | Format | Access |
|---|---|---|---|
| Synthetic warehouse OT generator | PLC registers, robot joint states, network flows | Parquet | `collectors/generate_synthetic.py` |
| MITRE ATT&CK for ICS v18 | Technique IDs, descriptions, tactics | STIX 2.1 JSON | Live fetch, CC BY 4.0 |
| CISA ICS Advisories | CVE records, vendors, CVSS scores | JSON + CSV | Live fetch with 25-row fallback |

**Honest scope note:** The project proposal describes Factory I/O + OpenPLC + ROS 2 as the data source. That stack is not yet set up. Phase 02 uses a pure-Python synthetic generator (`collectors/generate_synthetic.py`) that produces data shaped like real OT telemetry. The preprocessing and model code transfers directly when the real stack is online.

### 2.2 Collection Methods

- `collectors/generate_synthetic.py` runs 8 scenarios (4 normal, 4 attack) at 10 minutes each. Attack scenarios inject one of 7 ATT&CK for ICS techniques.
- `collectors/fetch_attack.py` downloads the official MITRE ATT&CK for ICS v18 STIX bundle (3.4 MB) from GitHub and extracts a flat lookup of our 7 target techniques.
- `collectors/fetch_cisa.py` fetches live CISA ICS advisories. On networks that block cisa.gov (such as this build environment), it falls back to a bundled 25-advisory sample from 2024-2025.

### 2.3 Storage

- Raw Parquet files in `data/raw/` (gitignored, regenerated by `make generate`)
- Processed outputs in `data/processed/`
- Threat intelligence in `data/threat/attack/` and `data/threat/cisa/`
- Fitted models in `models/`
- Metrics and charts in `reports/`

## 3. Week 5: Preprocessing and Feature Engineering

### 3.1 Cleaning

`pipeline/clean.py` drops rows with non-finite values and implausible physical readings (negative conveyor speeds above safe range, negative torque beyond noise floor, non-positive packet counts). On synthetic data this stage drops 0% because the generator produces clean values. The cleaning rules are in place for the real data in Phase 03.

### 3.2 Feature Engineering

`pipeline/features.py` builds three per-agent feature frames.

**Agent 1 (15 features from network windows):** pkt_count, pkt_size_mean, pkt_size_std, inter_arrival_mean_ms, unique_src_ips, unique_dst_ips, 5 protocol fractions (Modbus TCP, EtherNet/IP, PROFINET, HTTP, other), protocol entropy, size coefficient of variation, src/dst ratio, packet count deviation from 10-second rolling baseline.

**Agent 2 (18 features from CISA advisories):** advisory_id, vendor, product, asset_type (classified by keyword rules: plc, hmi, robot_controller, network_switch, engineering_workstation, other), CVSS v3, normalized CVSS, age in days, age score, exposure hint (web/remote/scada keyword flag), one-hot encoded asset type.

**Agent 3 (7 features per 1-second window per robot):** mean/max/std of |commanded - actual|, torque variance, timing jitter, non-primary command source fraction, command source entropy.

### 3.3 Train / Validation / Test Split

`pipeline/split.py` runs a 70/15/15 split stratified by `attack_class`. Random seed is fixed at 42 in `config.yaml`.

| Agent | Train | Val | Test |
|---|---|---|---|
| Agent 1 | 3,360 | 720 | 720 |
| Agent 3 | 10,080 | 2,160 | 2,160 |

Agent 2 does not get split because the fallback dataset has only 25 advisories; the full ranked list is evaluated instead.

## 4. Week 6: Exploratory Analysis and Baselines

### 4.1 Baseline Results (actual metrics from `make baseline`)

| Agent | Method | Primary Metric | Score | Interpretation |
|---|---|---|---|---|
| Agent 1 | Isolation Forest | F1 | 0.2424 | Low. Unsupervised model on 50/50 test is poorly calibrated by default. |
| Agent 1 | Isolation Forest | PR-AUC | 0.5452 | Marginal lift over random (0.50). Signal exists but weak. |
| Agent 1 | Isolation Forest | Precision | 0.5490 | Half of flagged rows are real attacks. |
| Agent 1 | Isolation Forest | Recall | 0.1556 | Catches only 15% of attack windows at default threshold. |
| Agent 2 | Rule-based CVSS + exposure + age | Top-10 mean CVSS | 8.66 | Beats bottom-10 (7.13). Ranker prioritizes high-severity. |
| Agent 2 | Rule-based | OT asset share in top-10 | 7 of 10 | 4 PLCs + 2 HMIs + 1 robot controller. |
| Agent 3 | Mahalanobis distance (p95) | F1 | 0.3742 | Low recall drags F1 down. |
| Agent 3 | Mahalanobis distance (p95) | PR-AUC | 0.7116 | Strong signal; threshold choice is the limiter. |
| Agent 3 | Mahalanobis distance (p95) | Precision | 0.7976 | When it flags, it is usually right. |
| Agent 3 | Mahalanobis distance (p95) | Recall | 0.2444 | Misses subtle attacks at p95. |

### 4.2 Observations

Agent 1 PR-AUC near 0.55 means Isolation Forest with default feature scaling struggles to separate attack windows from normal windows on this synthetic distribution. Agent 3 PR-AUC of 0.71 shows the robot integrity features carry much stronger signal than the aggregated network features. Agent 2's ranker correctly surfaces 7 of 10 OT-relevant assets in its top-10, which matches the warehouse-security context.

The low recall numbers on Agents 1 and 3 are expected for unsupervised baselines trained only on normal data. Phase 03 replaces both with supervised deep models that use the attack labels directly.

### 4.3 Orchestrator ATT&CK Tagging

`agents/orchestrator/attack_mapper.py` loads the real MITRE ATT&CK for ICS v18 lookup and tags each flagged event with technique IDs based on feature triggers. In a smoke test on 50 attack rows from each agent's test set, the mapper correctly tags Agent 3 attacks as T0836 Modify Parameter and T0832 Manipulation of View, matching the injected attack patterns.

Techniques currently covered: T0836, T0855, T0832, T0814, T0859, T0866, T0863.
